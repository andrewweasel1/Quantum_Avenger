# Quantum Avenger — Implementation Status & Remaining Work

> **Where the project is, and exactly what remains to fully realize it.** Companion to `ARCHITECTURE_ROADMAP.md` (current‑state architecture), `quantitative_math.md` (the rigor reference), and `OFFENSE_ROADMAP.md` (the signal‑generation / alpha build‑forward plan). The `PHASE_*_SPECIFICATION.md` files are the original build specs — historical; this doc + the roadmap are the current source of truth.

**Snapshot (audited 2026‑07‑10).** ~142 modules under `new_pipeline/` + a React SPA under `frontend/`; **495 tests pass / 5 skip** (optional `alpaca`/`torch`/`spaCy` + CUDA); **~94 % branch coverage**; `ruff` clean; fully seeded/deterministic. The whole pipeline runs **offline with no network** (`python new_pipeline/main.py pipeline` / `trade`), and the **React + FastAPI dashboard** (Overview / Analytics / Live Monitor / Engine Control) replaced Streamlit entirely. What remains is **operational**: live integration (incl. building the missing Ollama LLM client), the agentic‑RAG depth, the observability spine, and packaging/deploy — not core quant logic. The forward plan is phased for least backtracking: **(1) truth & contracts → (2) observability → (3) live data → (4) LLM + RAG → (5) paper trading → (6) package & deploy.**

## Remaining work — the phased plan (ordered for least backtracking)

Each phase only consumes contracts finalized in an earlier phase. **Phase 1 (truth & contracts) shipped:** config‑gated bearer‑token API auth (`api/auth.py`, `QA_API_TOKEN`, fail‑closed, threaded through the frontend client), dead‑code removal (the superseded `models/` package, unused utils helpers, `BaseDataHandler`), deletion of the broken Streamlit‑targeting deploy artifacts, CI extension (API deps fixed, frontend build job, gating `pip-audit`, Dependabot), and this docs sync.

### Phase 2 — Observability spine (offline) — ✅ SHIPPED
Real `HealthCheck` probes (absent state healthy, broken state degrades; the liveness script exits non‑zero); a process‑wide `MetricsCollector` incremented at the orchestrator's terminal nodes (executed / vetoed‑per‑gate), the runner (sessions), and the API (run launches); **`GET /metrics`** on FastAPI (auth‑gated when enabled) rendering counters + ledger‑derived KPI gauges + `dsr_value` (weakest active champion); `dispatch_current_alerts` at trading‑session end through `dashboard.alert_channels` (`console`/`webhook`, default off); `observability/{prometheus.yml,alert_rules.yml,grafana_dashboard.json}` re‑pointed at the actually‑emitted metric names (the fictional latency alert replaced by a NegativeSharpe rule). Verified by a live scrape showing real veto‑rate/Sharpe/drawdown/DSR values.

### Phase 3 — Live data plane (needs creds + egress) — ◐ IN PROGRESS (blocked on operator input)
- **Done (validated offline, 2026‑07‑11):** `requirements-live.txt` installs cleanly (alpaca‑py 0.43.5 + edgartools); every lazy SDK import in the five live adapters resolves against the real libraries; the full **SDK‑surface contract** holds (clients construct with dummy creds, all methods exist, request models accept exactly the adapters' kwargs) — pinned in `tests/unit/test_live_sdk_surface.py` (importorskip‑gated, runs wherever the SDKs are installed). New **`scripts/live_preflight.py`**: one command reporting SDKs / credentials / per‑host egress / a read‑only account snapshot, exit 0 when the Alpaca path is ready.
- **Blocked on operator input:** (a) `QA_ALPACA__API_KEY` / `QA_ALPACA__SECRET_KEY` (paper) are not set in this environment; (b) this sandbox's network policy **denies `api.gdeltproject.org` and `www.sec.gov`** (CONNECT 403) while allowing the Alpaca hosts — GDELT/EDGAR ingest must run after a policy change or on another host.
- **Remaining once unblocked:** `live_preflight` → `live_smoke` (account → tiny paper order → positions); real bars ingest; GDELT/EDGAR PIT news vault + fundamentals; the **first real‑data backtest launched and analyzed through the dashboard**; fix whatever real payloads shake loose in the coverage‑omitted mapping code.

### Phase 4 — LLM + agentic RAG — ✅ SHIPPED (offline; live validation = point it at a real Ollama)
- **`adapters/llm_ollama.py`**: the previously‑missing `OllamaLLMClient(LLMClient)` — stdlib urllib against `/api/generate` (JSON mode, temperature 0, injectable transport), consuming `FusionConfig.{ollama_endpoint, verdict_model|llm_model_name, sentiment_timeout}`. **Fail‑safe‑to‑veto**: any transport failure or unparseable reply degrades to NEUTRAL (grader rejects → no trade), never an exception mid‑session. Selected by `factory.build_llm_client` when **`fusion.enabled` + `ollama_endpoint`** (explicit flip — defaults ship a localhost endpoint, so the endpoint alone doesn't gate); the deterministic fake otherwise.
- **Embedder seam**: `rag.embedder: hashing | sentence_transformer` (+ `rag.embedding_model`) via `build_rag_engine`; `execution/embedders.py::SentenceTransformerEmbedder` is lazy/coverage‑omitted (fusion host, `requirements-fusion.txt` += sentence‑transformers) with importorskip tests.
- **Agentic evidence loop**: a new `evidence` node opens the trade graph — `rag.retrieve()` over the request's context corpus feeds the top‑k passages into the verdict prompt (weigh FOR/AGAINST) and the grader prompt (list evidence FOR / AGAINST / **MISSING**; approve only if supported). Gated by `rag.evidence_enabled` (default off); with it off, prompts are **byte‑identical** to before, so the deterministic fake's stances — and every existing test — are unchanged. Evidence is retrieved once and reused across grader‑retry loops.
- **Verified:** 15 new tests (all parse/fail‑safe paths of the Ollama client via injected transport; factory selection; evidence populated + top‑k respected + relevant passages outrank noise; grader retry reuses the index; legacy prompts byte‑stable) and the whole‑engine integration run passes with `QA_RAG__EVIDENCE_ENABLED=true`. Remaining live half: run against a real Ollama server + pull sentence‑transformer weights on the fusion host.

### Phase 5 — Paper trading end‑to‑end — integration only
- **Task:** `run_mode=paper` with real adapters + the real LLM: promoted champions trade the Alpaca paper account through the LangGraph graph; ledgers fill; the Live Monitor is genuinely live; a scheduled cadence (daily trade session, weekly retrain → promote) and an ops runbook.
- **Acceptance:** a multi‑day paper run with delivered alerts, live dashboards, and an auditable veto/trade ledger.

### Continuous track — deferred refinements (zero coupling; slot anywhere)
- **Cross‑sectional leakage:** the per‑sector matrix pools tickers, so same‑date / different‑ticker correlation is not addressed by time‑ordered CPCV — add a cross‑sectional purge or group‑by‑date scheme.
- **Options‑mode labels:** an options payoff label behind the same label interface as a future `RunMode` (the triple‑barrier interface already anticipates it).
- **Nonlinear causal screen:** a transfer‑entropy / causal‑discovery alternative to the linear Granger screen (the selector already keys off a `feature_selection_method` switch).
- **Frontend quality:** a test framework (vitest + RTL — the SPA has zero tests today), an error boundary, URL routing/deep‑linkable run views, and SSE adoption for live run logs (the endpoint exists; the UI polls).
- **Library‑only utilities, wire or keep as opt‑in:** `sequential_bootstrap` (bagged meta‑models), `hansens_spa` (gate option next to White's RC), `min_track_record_length` / `minimum_profit_hurdle` (promotion‑audit diagnostics).

### Alpha research roadmap (signal generation) — top‑6 status
The pipeline's *defenses* are deep but its *offense* is thin — ~11 microstructure/technical features → one XGBoost classifier per sector. `quantitative_math.md` Part II is the full toolbox; these are the **top‑6, prioritized by alpha‑per‑effort**, each of which must pass the existing CPCV + DSR/PBO/haircut/path‑DSR gauntlet before promotion. **`OFFENSE_ROADMAP.md` is the architecture + phased sequencing** that turns this list into shipped code (the three missing axes — cross‑sectional stage, IC/ICIR alpha eval, multi‑sleeve combination — and the P0→P5 plan).

1. **Cross‑sectional factor library + IC/ICIR eval** (Part II §B,§H) — momentum/reversal/value/quality/low‑vol/BAB/seasonality, ranked + sector/beta‑neutralized; evaluate with Information Coefficient / ICIR. **◐ factor library shipped** — `features/factors.py::add_cross_sectional_factors` (mom_12_1/reversal_21/low_vol/seasonality, sector‑neutral cross‑sectional z‑score, `xf_*` columns) behind `features.factor_set` (default‑off), wired into `build_training_frame`; the causal screen already retains `xf_low_vol`/`xf_mom_12_1` on the offline run. **IC/ICIR eval shipped (P2)** — `evaluation/alpha_eval.py` (universe‑wide rank‑IC, ICIR, t‑stat, breadth, hit‑rate, decay → `alpha_eval.json`), golden‑pinned. **Value/quality shipped (Phase C):** a point-in-time fundamentals layer (`adapters/` `FundamentalsSource` + fake/static/EDGAR, `data/fundamentals.py` backward as-of join) feeds `book_to_market`/`earnings_yield`/`roe` cross-sectional factors. **Pending:** promoting a standalone factor *sleeve* (vs. factors‑as‑features today) arrives with the P4 portfolio layer. *Biggest expected lift — most equity alpha lives here.*
2. **Information bars + fractional differentiation** (§A) — min‑`d` frac‑diff for stationary‑with‑memory features; dollar/volume/imbalance bars upstream. **◐ frac‑diff (+ vol/microstructure families) shipped** — `features/{fracdiff,vol_estimators,microstructure,extended}.py` behind `features.extended_features` (default off), golden‑pinned; frac‑diff passes the ADF stationarity assertion (log‑price −1.35 → −3.42). **GARCH(1,1) conditional volatility** also shipped (`features/garch.py`: MLE fit on a warmup window, causal variance recursion, leak-free post-warmup). **Pending:** information bars (need intraday/tick data — a bar resampler over a tick source).
3. **Meta‑labeling** (§G) — a secondary model deciding whether to *act on* / how to *size* the triple‑barrier primary. **✅ shipped** — `tournament/meta_labeling.py` + director wiring (`_meta_labeling`) records an OOS primary‑vs‑meta verdict (precision/recall/F1 + `improved`) in the candidate manifest, behind `tournament.enable_meta_labeling` (default off, read‑only). **Pending:** persist + deploy the meta booster (size live bets by meta `P(win)`) when meta‑labeling is wired into live execution.
4. **Stat‑arb: cointegration / Ornstein‑Uhlenbeck** (§C) — a market‑neutral second strategy family. **✅ shipped + validated** — `tournament/stat_arb.py` (self‑contained ADF, Engle‑Granger pairs, OU half‑life, causal mean‑reversion rule) + `pipeline._run_stat_arb`, behind `stat_arb.enabled`. Pairs are selected and hedge‑fit **in‑sample**, traded **out‑of‑sample**, then **gated**: each sleeve's OOS returns get a Deflated Sharpe deflated by the number of pairs searched (`validated` flag), White's Reality Check runs over the family, and only validated sleeves combine into an exact date‑aligned HRP book. **Johansen multivariate baskets** (`tournament/johansen.py`: reduced‑rank VECM eigenproblem → leading cointegrating vector, ADF‑confirmed) trade per sector behind `stat_arb.use_johansen`. *Complete (price‑based).*
5. **Portfolio layer: HRP/NCO + RMT/Ledoit‑Wolf denoising** (§H,§F) — combine sleeves into target weights on a denoised covariance. **✅ shipped** — `portfolio/` package: `denoise_covariance` (RMT), `ledoit_wolf_covariance` (sklearn), `hrp_weights`/`inverse_variance_weights`, `combine_returns`; `run_offline_pipeline` writes a per‑sector book to `portfolio.json` (behind `portfolio.enabled`). Both books are now **exact**: the **stat‑arb** book combines date‑indexed OOS sleeves, and the **cross‑sector champion** book aggregates each champion to a daily sector return (mean across the sector's tickers per date), date‑aligns the sectors, and HRP‑combines on the real covariance (genuine weights + `book_sharpe`). Allocation methods: HRP, **NCO** (nested clustered min‑variance), inverse‑variance, **IC/Sharpe‑weighting**, equal. *Complete.*
6. **Data‑snooping guards: White's Reality Check / Hansen's SPA** (§J) — multiple‑*strategy* bootstrap tests complementing per‑strategy DSR/PBO. **✅ shipped + gateable** — `evaluation/reality_check.py` (`whites_reality_check`, `hansens_spa`; shared stationary block bootstrap), golden‑pinned (noise ≈ 0.7, a skilled best‑of‑20 ≈ 0.003). Recorded per sector over the grid‑search trials (`reality_check_enabled`) and, when `reality_check_gate_enabled`, **gates promotion** (reject when the best‑trial p‑value > `reality_check_threshold`). Also runs as the family guard inside stat‑arb validation.
